        تَقّه بزن — اطلاعات فنی پروژه (Technical Overview)

────────────────────────────────────────────────────────────────────
۱) زبان‌ها و تکنولوژی‌های استفاده‌شده
────────────────────────────────────────────────────────────────────
• JavaScript (ES2022, ES Modules بومی)
  → کل منطق بازی، رابط کاربری، فیزیک، شبکه و ذخیره‌سازی.
  → بدون هیچ Build Step و بدون Bundler. مرورگر مستقیماً ماژول‌ها را
    با <script type="module"> می‌خواند. یعنی صفر ابزار جانبی لازم است.

• HTML5
  → فایل index.html تنها نقطه‌ی ورود. عنصر <canvas> برای رندر سه‌بعدی.

• CSS3 (بدون فریم‌ورک، بدون Tailwind/Bootstrap)
  → theme.css: متغیرهای رنگ، تایپوگرافی، اسکرول، دکمه‌ها.
  → screens.css: تمام صفحه‌ها، HUD، کنترل لمسی و Media Queryهای
    ریسپانسیو (موبایل / تبلت / لپ‌تاپ / دسکتاپ / TV با Safe Area).
  → پشتیبانی کامل RTL/LTR با ویژگی dir و خصوصیات منطقی
    (margin-inline, padding-inline) نه left/right ثابت.

• WebGL 2 از طریق three.js نسخه r169
  → موتور سه‌بعدی. به‌صورت Vendored در vendor/three.module.min.js
    قرار دارد (۶۷۲KB، مجوز MIT) تا بازی آفلاین و بدون CDN کار کند.
  → انتخاب دلیل: سبک، ESM بومی، بدون نیاز به Build، سازگار با
    مرورگر کنسول‌های بازی.

• Web Audio API
  → کل صداها به‌صورت Procedural تولید می‌شوند (موتور، باد، تصادف،
    تقّه، سکه). هیچ فایل صوتی در پروژه نیست ⇒ حجم بسیار کم.

• Supabase (PostgreSQL + Auth + Storage + RLS)
  → بک‌اند. احراز هویت، پروفایل، لیدربورد، آواتار و Audit Log.
  → منطق حساس (خرید موتور، ارتقاء، ثبت امتیاز) داخل Postgres
    Function اجرا می‌شود، نه در مرورگر ⇒ ضد تقلب.

• LocalStorage / IndexedDB
  → حالت مهمان و کش آفلاین. صف ارسال (Queue) برای وقتی شبکه قطع است.

• Service Worker + PWA Manifest
  → اجرای آفلاین، نصب روی گوشی، مدیریت نسخه با کلید VERSION.

• Gamepad API
  → پشتیبانی واقعی Xbox / PlayStation / Generic با Trigger آنالوگ،
    لرزش (Vibration) و Remapping کلیدها.

• Node.js
  → فقط برای ابزار توسعه: سرور محلی (tools/serve.cjs) و تست‌ها.
    در محصول نهایی هیچ وابستگی Node وجود ندارد.

• Playwright
  → تست خودکار مرورگر (فقط زمان توسعه، در بسته‌ی نهایی نیست).

۳) معماری
────────────────────────────────────────────────────────────────────
• الگوی ماژولار: هر ماژول یک شیء با ساختار زیر است:
      export default { id, deps: [], async init(ctx), async start(ctx), dispose() }
• ارتباط بین ماژول‌ها فقط از دو راه:
      ctx.bus     → رویدادها (Event Bus)
      ctx.use(id) → دسترسی به سرویس ماژول دیگر
  هیچ ماژولی مستقیماً به داخلِ ماژول دیگر دست نمی‌زند.
• ۲۲ ماژول مستقل: game, physics, procgen, ui, audio, input,
  localization, profile, auth, db, leaderboard, economy, motorcycle,
  repair, taqehgame, admin, settings, device, errors, analytics,
  cheats, save.
• صفر وابستگی زمان اجرا (Zero Runtime Dependency) به‌جز three.js.

۴) عملکرد و بهینه‌سازی
────────────────────────────────────────────────────────────────────
• Object Pooling برای سکه، ترافیک، مانع و ذرات.
• حذف اشیاء خارج از دید (Frustum + Distance Culling).
• سه پریست کیفیت Low / Medium / High + سیستم تطبیقی خودکار.
• Procedural Generation به‌جای فایل Asset ⇒ حجم کل زیر ۱ مگابایت.
• هیچ تصویر یا صدای خارجی دانلود نمی‌شود.

────────────────────────────────────────────────────────────────────
۵) امنیت
────────────────────────────────────────────────────────────────────
• هیچ Secret، Service Role Key یا رمزی در Frontend نیست.
• Row Level Security روی تمام جدول‌ها فعال است.
• رمز کاربران هرگز قابل مشاهده نیست، حتی برای Admin (فقط Reset).
• رمزها و اطلاعات حساس هرگز در Audit Log ثبت نمی‌شوند.
• نقش Admin از دیتابیس خوانده می‌شود (profiles.is_admin)، نه از کلاینت.

────────────────────────────────────────────────────────────────────
۶) اجرا
────────────────────────────────────────────────────────────────────
• محلی:      یک سرور استاتیک ساده کافی است (به‌خاطر ES Modules نمی‌توان
             فایل را مستقیم با file:// باز کرد).
• GitHub Pages: پوشه را Push کنید و Pages را روی شاخه فعال کنید.
             تمام مسیرها نسبی‌اند و بازی بدون تنظیم اضافی کار می‌کند.
             حالت مهمان، امتیاز، Top 10 و تغییر نام روی Pages نیز
             کامل کار می‌کنند (ذخیره در LocalStorage).
