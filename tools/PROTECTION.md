# محافظت از کد — راهنمای انتشار

## ساخت نسخه‌ی محافظت‌شده

```bash
npm install          # فقط یک‌بار (esbuild)
npm run build        # خروجی در dist/
```

خروجی `dist/` همان چیزی است که روی GitHub Pages منتشر می‌شود.

---

## چه چیزی محافظت می‌شود

| لایه | کار | تضمین |
|---|---|---|
| **Bundle** | ۵۲ فایل ماژول → یک فایل | ساختار پوشه‌ها، نام فایل‌ها و مرز ماژول‌ها کاملاً از بین می‌رود |
| **Minify** | نام متغیرها و توابع → `a`,`b`,`c`… + حذف همه‌ی کامنت‌های فارسی | کد عملاً ناخوانا |
| **AES-256-GCM** | بدنه‌ی کد رمز می‌شود، فقط در حافظه باز می‌شود | روی دیسک و در Network tab هیچ‌وقت متن خام نیست |
| **SHA-256** | مهر یکپارچگی، پیش از اجرا بررسی می‌شود | **تغییر یک بایت ⇒ بازی بالا نمی‌آید** |
| **SRI** | `integrity` روی تگ script | مرورگر خودش فایل دستکاری‌شده را اجرا نمی‌کند |
| **guard.js** | راست‌کلیک، F12، Ctrl+Shift+I/J/C، Ctrl+U/S، انتخاب متن، کشیدن | منوی راست‌کلیک هرگز باز نمی‌شود |

## آنچه باید صادقانه بدانید

**رمزگذاری غیرقابل بازگشت روی کد فرانت‌اند از نظر ریاضی ممکن نیست.** مرورگرِ
کاربر باید کد را اجرا کند، پس کلید ناچار داخل همان بسته است. هر ابزاری که
خلاف این ادعا کند دروغ می‌گوید.

معنای عملی‌اش:

- کاربر عادی و نیمه‌حرفه‌ای: **هیچ راهی** برای دیدن یا تغییر کد ندارد.
- مهندس مصمم با دیباگر: می‌تواند به کدِ minify‌شده برسد — ولی نمی‌تواند
  نسخه‌ی منتشرشده را **تغییر دهد**، چون مهر SHA-256 جلویش را می‌گیرد. این
  بخش تضمینِ قطعی دارد.

به همین دلیل **امنیت واقعی اقتصاد بازی جای دیگری است**: قوانین RLS و
اعتبارسنجی سمت سرور در Supabase. سکه، امتیاز و موتورهای خریداری‌شده روی
سرور تأیید می‌شوند، نه در مرورگر. آن لایه با این بسته تغییری نکرده و
دست‌نخورده باقی است.

### درباره‌ی devtools
میان‌بُرهای صفحه‌کلید گرفته می‌شوند، اما **هیچ صفحه‌ای نمی‌تواند منوی خود
مرورگر را غیرفعال کند**. روش‌های رایجِ «تشخیص devtools» (حلقه‌ی `debugger`
یا سنجش اندازه‌ی پنجره) عمداً استفاده نشده‌اند: مرورگرهای مدرن دورشان
می‌زنند، روی موبایل false positive می‌دهند و فقط بازی را کند می‌کنند.

## انتشار روی GitHub Pages

محتویات `dist/` را در شاخه‌ی `gh-pages` (یا پوشه‌ی `/docs`) قرار دهید.

- همه‌ی مسیرها **نسبی** هستند → زیر `/<repo>/` درست کار می‌کند.
- `.nojekyll` موجود است → پوشه‌های `_`دار نادیده گرفته نمی‌شوند.
- `three.js` از طریق **importmap** حل می‌شود (نه مسیر نسبی)، چون کد از
  داخل Blob URL اجرا می‌شود و مسیر نسبی آنجا معنا ندارد.

### مهم: بعد از هر تغییر در سورس
`npm run build` را دوباره اجرا کنید. اگر `dist/` قدیمی بماند، هش با کد
نمی‌خواند و بازی با پیام یکپارچگی متوقف می‌شود — این رفتار عمدی است.

## سورس اصلی

`src/` را در ریپازیتوری خصوصی نگه دارید و فقط `dist/` را منتشر کنید.
بدون سورس، نگهداری و توسعه‌ی بعدی ممکن نیست.
